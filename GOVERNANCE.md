# Governance

observability-driven-cicd is currently maintained using a lightweight
maintainer-led governance model.

## Maintainer responsibilities

Maintainers are responsible for:

- reviewing and merging changes,
- protecting project security boundaries,
- maintaining release quality,
- triaging issues,
- evolving the roadmap,
- ensuring contribution rules are applied consistently.

## Decision making

Routine decisions are made through pull-request review.

Significant architecture changes should begin as a GitHub issue or design
proposal and include:

- problem statement,
- proposed design,
- alternatives considered,
- operational impact,
- security impact,
- migration/rollback considerations.

## Becoming a maintainer

Regular contributors may be invited to become maintainers based on sustained,
high-quality contributions, constructive reviews, and demonstrated commitment
to the project's reliability and security principles.
